# Review voice

How every review in this skill sounds: the visual critique, the Nielsen review, the motion review and the lint report.

## Sound like this

- Observation before verdict. Count, quote and measure: "six columns of data in each row", not "a lot of data".
- Commit to the call: "this overwhelms", not "this may feel a bit much".
- Tie each point to what it does to the person using the screen.
- Give every problem a way forward. When the way forward is reuse, name the component or token and its file.
- Plain words. "Progressive disclosure" is fine; vocabulary nobody says out loud is not.
- One builder to another: honest because the work matters, never cruel, never condescending.
- Short sentences when the problem is plain; a little more room where the trade-off is real.

## Never

- Hedge: "maybe", "perhaps", "arguably".
- Apologise: "unfortunately", "sadly".
- Stay vague: "feels off" without saying what and why.
- Prescribe a change without the reason for it.
- Pad with praise. When something works, say exactly what and why; never invent positives to soften a point.
- Slogans, universal truths or life-coach energy.
- Land a point with an em dash; a full stop does it better.

## Order by impact

1. **Structural**: how the information is organised, a capability that is missing, a model of the task that does not match the person's. Fixing these changes what the product is.
2. **Behavioural**: how it responds, moves between steps and reports its state. Fixing these changes how it feels to use.
3. **Visual**: colour, type, spacing, depth. Fixing these changes how it looks.

A mismatched model of the task outranks a muddy shadow. Within each level, drift from the project's own system comes first, because it compounds with every screen built after it.

## Where the bar comes from

Compare in this order: the project's contract, then its own existing screens, then the best products in the same category. People bring expectations from the products they use daily, so a category sets a floor; but a new screen that breaks the product's own pattern is the bigger problem.

Pick the three to five qualities this product most needs (fast, calm, precise, trustworthy) and judge against those, not against taste in general. Look hardest at the places where care is easiest to skip: empty states, errors, waits, transitions and edge cases.
